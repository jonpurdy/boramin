# Regression checks and diagnostics

Run commands from the repository root with the configured Xcode toolchain. The probes use disposable fixtures/preferences; local-file test inputs do not add local-file opening to the app. Confirm actual decoded/rendered video rather than an advancing audio clock. Device installation and live iCloud tests are separate actions.

## Fast host checks

These suites need no device, SMB connection, or iCloud account. Connection tests cover multiple servers/accounts, stable edits, local selection, connection deletion (including synced deletion, shared credentials, selection repair and relaunch), and legacy favorite/Watching migration. The connection suite uses disposable Keychain entries and requires host Keychain access; Swift macro compilation also requires a toolchain environment that permits compiler plugins. Run outside a restrictive agent sandbox when necessary:

```sh
set -e
mkdir -p build/HostTests
swiftc -module-cache-path build/HostTests/ModuleCache Player/PlaybackPositions.swift Tests/PlaybackPositionsTests.swift -o build/HostTests/positions
swiftc -module-cache-path build/HostTests/ModuleCache Player/MediaMetadata.swift Tests/MediaMetadataTests.swift -o build/HostTests/metadata
build/HostTests/metadata
build/HostTests/positions
swiftc -module-cache-path build/HostTests/ModuleCache Player/Favorites.swift Tests/FavoritesTests.swift -o build/HostTests/favorites
build/HostTests/favorites
swiftc -module-cache-path build/HostTests/ModuleCache Player/ConnectionPreferences.swift Tests/ConnectionPreferencesTests.swift -o build/HostTests/connections
build/HostTests/connections
swiftc -module-cache-path build/HostTests/ModuleCache -parse-as-library Player/ConnectionPreferences.swift Player/Favorites.swift Player/PlaybackPositions.swift Shared/ICloudSync.swift Tests/CloudSyncSchedulingTests.swift -o build/HostTests/cloud-scheduling
build/HostTests/cloud-scheduling
```

October 26 verification: both repaired full scripts passed with normal host access, including Keychain, CloudKit scheduling, 600 hardware-decoded VP9 frames, H.264/HEVC configuration and seek checks, native MP4 track groups, and Mac window rendering/lifecycle tests.

## Playback and subtitle harnesses

`python3 tools/test_aether_software.py --probe software` generates an unsigned, unsandboxed Mac test project from the production project, replacing only its app entry point. It does **not** build or run it. Subtitle/software modes are `software`, `ass`, and `external`; the full suites below also use `native`, `hardware`, and `codecs`. After generating the desired mode:

```sh
xcodebuild -project build/AetherSoftwareTests/Probe.xcodeproj \
  -scheme 'BoraMin macOS' -configuration Release \
  -destination 'platform=macOS,arch=arm64' \
  -clonedSourcePackagesDirPath build/AetherPackages \
  -derivedDataPath build/AetherSoftwareTests/Derived build
```

Run the resulting `build/AetherSoftwareTests/Derived/Build/Products/Release/BoraMin.app/Contents/MacOS/BoraMin` with the mode's fixture argument:

| Mode | Fixture argument / preparation |
| --- | --- |
| `software` | Path to a synthetic MPEG-4 Part 2 AVI with two MP3 audio tracks. See [AetherEngine playback](../docs/AetherEngine-playback.md). |
| `ass` | `build/ASSTests/styled.mkv`, generated by `python3 tools/create_ass_fixture.py`. |
| `external` | Absolute `build/ASSTests` directory; use the complete preparation/run sequence in [external subtitle tests](../docs/External-subtitles.md#local-regression-probe). |

Building a different mode overwrites the same generated project/product. These probes can open temporary test windows. Real-SMB mode is optional; do not use private defaults for routine isolated tests.

The external subtitle probe also requires `python3 tools/create_pgs_fixture.py` alongside the ASS/native-MP4 fixtures in [external subtitle tests](../docs/External-subtitles.md#local-regression-probe). This creates a synthetic native-video MKV with PGS and SRT tracks, exercising decoded PGS cues and actual production-overlay pixels without ASS or sidecars, plus Off/reselection/seek and native-text switching.

After a normal app build, verify FFmpeg isolation with `python3 tools/verify_media_linkage.py /absolute/path/to/BoraMin.app`.

### Full bridge/hardware and Mac window suites

```sh
python3 tools/run_tests.py
sh tools/test_macos_playback.sh
```

`run_tests.py` runs the focused host suites (including route prediction and local metadata cache invalidation/eviction), C demux/audio/range-IO/keyframe checks, compressed VP9 identity and PCM comparison, confirmed hardware VP9 decoding in WebM and MKV, and H.264/HEVC configuration/B-frame checks. It requires Homebrew FFmpeg and the adjacent `atv vp9-av1 testing` fixtures (`fixtures/middle.webm`, `fixtures/ready/sample.ivf`, and the VP9 HDR fixture MKV). Keychain and compiler plugins need normal host access.

`test_macos_playback.sh` creates disposable native-track MP4 and H.264 MKV fixtures, then checks the actual Mac window adapter: rendered video, native MP4 audio/subtitle groups, seeks, pause/resume, consecutive windows, teardown, and completion dismissal. Its MKV fixture exercises the original demux/sample-buffer adapter directly, not automatic AetherEngine routing; use the engine probes for that coverage.

Both playback stages now use `tools/run_playback_probe.py`, which generates the Xcode-derived project, builds with production dependencies, verifies FFmpeg linkage, and runs the selected probe with a timeout. Build logs are `build/AetherSoftwareTests/MODE-build.log`. Modes include `native`, `hardware`, and `codecs` in addition to the modes above. Run these scripts/probes sequentially because their generated project/product is shared. No installation, server credentials, or iCloud sync is involved in these playback fixtures.

Keep the [verification history](verification.txt) and codec investigations as dated evidence, not as substitutes for current test runs.

## Device playback checks

These hooks exercise the existing app/player. None runs during an ordinary launch. Device deployment is a separate explicit action; building a project does not authorize installing it on a device currently in use.

- `--stream-smoke-test SHARE RELATIVE_PATH`: stream with saved SMB credentials. Add `--no-playback-history` to avoid modifying bookmarks.
- `--exercise-stream-controls` / `--exercise-mkv-controls`: pause and seek checks; MKV checks also inspect displayed video frames.
- `--exercise-player-lifecycle`: open/dismiss three times, verifying teardown. `--test-second-video RELATIVE_PATH` substitutes the second video; `--probe-frames-only` requires video confirmation.
- `--vp9-diagnostics`: timestamps, queued/late frames, network/cache metrics and thermal state. Cache/read-size overrides are documented in the [streaming investigation](VP9-streaming-investigation.md).
- `--native-tracks-smoke-test --exercise-native-tracks --no-playback-history`: after `python3 tools/create_native_tracks_fixture.py`, copy `build/NativeTrackTests/native-tracks.mp4` into the app's Library/Caches directory to test native audio/subtitle selections.
- Legacy local VP9 control: generate the TV project with `BORAMIN_SMOKE_FIXTURE=/absolute/path/smoke.webm python3 tools/create_project.py`, then use `--smoke-test`. Regenerate without that environment variable afterward. This measures local decoding, not SMB streaming.

The isolated `NativeVP9Probe.swift` project is generated by `tools/create_native_vp9_probe.py --make-fixtures`; see [native VP9](Native-VP9-investigation.md) and [retired streaming remux investigation](Streaming-remux-investigation.md) for historical results. The production VP9 remux experiment and its dedicated fragment tests/fault exercises were removed November 3; normal frame/lifecycle probes remain. `NativeAudioProbe.swift` is the retained source of the one-off AAC investigation; its generated app/media have been removed. Temporary logs under `/tmp` and generated products under `build/` are not durable evidence; summarized outcomes are in the committed notes.

## Synthetic CloudKit probe (optional)

`CloudSyncProbe.swift` and `CloudSyncProbeScreen.swift` are test-only fixtures. Normal iOS and Mac builds do not compile them. Enable the iOS probe explicitly:

```sh
python3 tools/create_project.py --include-cloud-probe
# Build the iOS project, then use --probe or --run-id UNIQUE_RUN --cloud-action ACTION.
# After testing, restore the normal project definition:
python3 tools/create_project.py
```

The probe uses the separate `BoraMinSyncProbe-v1` zone and synthetic data. Its delegate skips production sync in probe mode, including background and push handling. Never enter real NAS credentials. The probe uses the current shared app bundle identity; probe-mode data has separate storage/Keychain records. Use a unique run ID and the same iCloud account on test devices; create synthetic records on one device, sync the other, and compare. Never infer Production sync from a Development-only probe.

Production sync has separate `--icloud-sync-check` and `--icloud-preference-check` diagnostics; the latter deliberately edits a preference and requires restoring it afterward. They are not routine app behavior.

## CloudKit scheduling regression

`CloudSyncSchedulingTests.swift` checks that the production engine-task factory discards inherited delegate task-local context while retaining MainActor isolation and cancellation. It runs without a CloudKit account or network access and is included in `tools/run_tests.py`. This guards against the CloudKit task-local-context termination previously observed on Apple TV.

## Connection opening regression

`python3 tools/test_smb_socket.py` compiles the vendored libsmb2 C sources with their Apple configuration and runs a local TCP-reset regression. It connects using production `smb2_connect_async`, resets the loopback peer, then sends an actual queued SMB echo through production `writev`. With the default SIGPIPE disposition, the original code terminates with signal 13; the patched socket returns `EPIPE` and an SMB error while the process survives. It requires normal host access for loopback sockets, no NAS, credentials, device or SMB server. The main suite includes it. This isolates the socket failure mechanism; physical-device navigation/background-return validation remains separate.

`python3 tools/run_playback_probe.py browsing offline` runs the extracted SMB service's offline checks: mixed file/folder natural sorting, hidden-file filtering, metadata/path mapping, server validation, and cancellation before a metadata read. It needs no server, device, Keychain, or iCloud account.

`python3 tools/run_playback_probe.py cancellation offline` checks explicit browser cancellation, cancellation before startup, stalled callback waiters, late results/errors, completion/cancellation races, and isolation from a newer operation. It also checks fresh SMB-session replacement, returning to the Connections list without a foreground reconnect, cancelled blocking reads/preparation, and normal loopback-listener startup. No server, device, or iCloud account is required; test preferences are disposable. Underlying SDK callbacks may finish later, but must never publish cancelled results or disturb a newer operation.

The same cancellation probe fills a retained playback source's compressed cache and verifies that stopping its transport clears cached bytes without clearing another source or resetting transfer totals. A stalled-read case checks that cancellation lets worker cleanup acquire the cache lock, while dismissal remains free to run on MainActor and late bytes cannot refill the stopped cache.

`SMBDeletionProbe.swift` is an opt-in integration check for a disposable local Samba share only: `python3 tools/run_playback_probe.py deletion /absolute/path/to/disposable-share`. It expects `TESTMEDIA` at `127.0.0.1:1445` with test-only account `boramin-test` / `test-only`, backed by that directory. It creates uniquely named temporary files, verifies their removal on the backing filesystem, and checks that denied deletion keeps the row and reports an error. Never point this fixture at a media share. The original investigation made no production deletion change. The offline browsing suite now also checks associated-subtitle matching/shared-video protection and video-first deletion ordering, failure isolation, and partial-result reporting without contacting a server. Live multi-file SMB deletion has not been verified by those offline checks.

`python3 tools/run_playback_probe.py connections /absolute/path/to/local-preferences.plist` tests the production Browser model with an isolated preferences suite and existing local Keychain credentials. This is an opt-in, read-only live-server check requiring at least two saved connections with enumerable shares. It checks opening, switching, returning to Connections, and reconnecting when the awaiting screen task is cancelled. Never commit the preferences fixture or print its server/credential fields. It does not deploy an app or activate iCloud.

Add `--browse` after the fixture path to also check root directory ordering/filtering, favorite identity and reopening, and parent navigation back to shares. Use this with connections that enumerate shares, without a pinned direct share. The checks only read remote files/directories.

Add the pass-through argument with `python3 tools/run_playback_probe.py connections -- /absolute/path/to/local-preferences.plist --watching` to test an active Watching file: uncached route discovery over SMB and reuse of its isolated local metadata cache. The fixture must include that file’s saved metadata and playback position.

Use `--stress` after the fixture path to repeat the connection cycle ten times (40 opening/reconnection attempts for two servers). `Tests/ConnectionRetryTests.swift`, included in `tools/run_tests.py`, checks one-shot transient recovery, the two-attempt cap, no authentication/path retries, and cancellation.

## HTTP/Caddy integration

`python3 tools/test_http.py` builds the isolated `http` probe and runs a disposable Caddy server plus an adversarial HTTP server, using generated media and synthetic credentials. Requires `caddy` and `ffmpeg` on PATH. Run sequentially with all other playback probes. The harness removes its diagnostic app afterward and stops both servers; build/output logs remain under ignored `build/HTTPValidation/` and `build/AetherSoftwareTests/http-build.log`.

Coverage includes Caddy JSON (including encoded filenames and nested folders), Basic authentication, range byte identity, 128 MiB cache eviction, ignored/malformed/truncated/oversized/changed responses, encoded bodies, origin/base-path redirects, invalid listings, cancellation, favorites and Watching persistence/reopening, and matching external subtitle loading. Its Mac checks exercise native AVPlayer, Aether native/software and original VP9 routes with video-output/rendering evidence before and after seeks, plus native pause and teardown. It also checks per-reader cancellation and transport lifetime after the browsing session is released. These checks do not contact saved servers, use private defaults, activate iCloud, deploy to devices, or establish physical iOS/tvOS playback. Connection/model suites also cover HTTP credentials, additive profile fields, fixed types and unchanged SMB data.

## Cloud connection identity regression

`CloudConnectionIdentityTests.swift`, included in `python3 tools/run_tests.py`, uses synthetic records and isolated preferences; it does not instantiate the production sync engine or contact CloudKit. It first reproduces the old conflicting legacy-record/UUID-payload behavior, then checks both application orders from missing, correct and duplicate local sets, repeated application/relaunch, cache/outbox serialization, pending edits, stable favorite/Watching/subtitle references, and distinct same-host and HTTP profiles. Unverifiable IDs and cross-profile deletions must not be applied.

## tvOS 26.2 simulator

On Apple Silicon, build the private bridge dependencies with `python3 tools/build_ffmpeg.py --platform tvos-simulator`, then select the running tvOS 26.2+ simulator under the BoraMin tvOS scheme. Device libraries are rebuilt separately with `--platform tvos`. Both use the same pinned FFmpeg source and private framework boundary; the simulator does not substitute Mac or device binaries. iOS Simulator remains unconfigured. Simulator browsing/debugging can help reproduce list-navigation faults, but does not establish physical-device playback or tvOS 27 behavior.

Embedded thumbnail regression checks: `python3 tools/test_thumbnails.py` (also included in `tools/run_tests.py`). These generate temporary synthetic PNG/MKV/MP4 fixtures and verify exact embedded bytes, cover selection, cancellation/output/read bounds, downsampling with alpha, local persistence, file invalidation, purge recovery, negative caching, eviction, legacy Top Shelf snapshots and local artwork filename validation. They do not access remote media or exercise visible UI rendering.

To repeat artwork extraction against a built private framework, add `--framework-dir build/Thumbnails/Build/Products/Debug/BoraMin.app/Contents/Frameworks` to `tools/test_thumbnails.py`.
