# Regression checks and diagnostics

Run commands from the repository root with the configured Xcode toolchain. The probes use disposable fixtures/preferences; local-file test inputs do not add local-file opening to the app. Confirm actual decoded/rendered video rather than an advancing audio clock. Device installation and live iCloud tests are separate actions.

## Fast host checks

These suites need no device, SMB connection, or iCloud account. The connection suite uses disposable Keychain entries and requires host Keychain access; Swift macro compilation also requires a toolchain environment that permits compiler plugins. Run outside a restrictive agent sandbox when necessary:

```sh
set -e
mkdir -p build/HostTests
swiftc -module-cache-path build/HostTests/ModuleCache Player/PlaybackPositions.swift Tests/PlaybackPositionsTests.swift -o build/HostTests/positions
build/HostTests/positions
swiftc -module-cache-path build/HostTests/ModuleCache Player/Favorites.swift Tests/FavoritesTests.swift -o build/HostTests/favorites
build/HostTests/favorites
swiftc -module-cache-path build/HostTests/ModuleCache Player/ConnectionPreferences.swift Tests/ConnectionPreferencesTests.swift -o build/HostTests/connections
build/HostTests/connections
swiftc -module-cache-path build/HostTests/ModuleCache -parse-as-library Player/ConnectionPreferences.swift Player/Favorites.swift Player/PlaybackPositions.swift Shared/ICloudSync.swift Tests/CloudSyncSchedulingTests.swift -o build/HostTests/cloud-scheduling
build/HostTests/cloud-scheduling
```

October 26 verification: both repaired full scripts passed with normal host access, including Keychain, CloudKit scheduling, 600 hardware-decoded VP9 frames, H.264/HEVC configuration and seek checks, native MP4 track groups, and Mac window rendering/lifecycle tests.

## Playback and subtitle harnesses

`python3 tools/test_aether_software.py --probe software` generates an unsigned, unsandboxed Mac test project from the production project, replacing only its app entry point. It does **not** build or run it. Subtitle/software modes are `software`, `ass`, and `external`; the full suites below also use `native`, `hardware`, and `codecs`. After generating the desired mode:

```sh
xcodebuild -project build/AetherSoftwareTests/Probe.xcodeproj \
  -scheme 'BoraMin macOS' -configuration Release \
  -destination 'platform=macOS,arch=arm64' \
  -clonedSourcePackagesDirPath build/AetherPackages \
  -derivedDataPath build/AetherSoftwareTests/Derived build
```

Run the resulting `build/AetherSoftwareTests/Derived/Build/Products/Release/BoraMin.app/Contents/MacOS/BoraMin` with the mode's fixture argument:

| Mode | Fixture argument / preparation |
| --- | --- |
| `software` | Path to a synthetic MPEG-4 Part 2 AVI with two MP3 audio tracks. See [AetherEngine playback](../docs/AetherEngine-playback.md). |
| `ass` | `build/ASSTests/styled.mkv`, generated by `python3 tools/create_ass_fixture.py`. |
| `external` | Absolute `build/ASSTests` directory; use the complete preparation/run sequence in [external subtitle tests](../docs/External-subtitles.md#local-regression-probe). |

Building a different mode overwrites the same generated project/product. These probes can open temporary test windows. Real-SMB mode is optional; do not use private defaults for routine isolated tests.

After a normal app build, verify FFmpeg isolation with `python3 tools/verify_media_linkage.py /absolute/path/to/BoraMin.app`.

### Full bridge/hardware and Mac window suites

```sh
python3 tools/run_tests.py
sh tools/test_macos_playback.sh
```

`run_tests.py` runs the focused host suites, C demux/audio/range-IO/keyframe checks, compressed VP9 identity and PCM comparison, confirmed hardware VP9 decoding in WebM and MKV, and H.264/HEVC configuration/B-frame checks. It requires Homebrew FFmpeg and the adjacent `atv vp9-av1 testing` fixtures (`fixtures/middle.webm`, `fixtures/ready/sample.ivf`, and the VP9 HDR fixture MKV). Keychain and compiler plugins need normal host access.

`test_macos_playback.sh` creates disposable native-track MP4 and H.264 MKV fixtures, then checks the actual Mac window adapter: rendered video, native MP4 audio/subtitle groups, seeks, pause/resume, consecutive windows, teardown, and completion dismissal. Its MKV fixture exercises the original demux/sample-buffer adapter directly, not automatic AetherEngine routing; use the engine probes for that coverage.

Both playback stages now use `tools/run_playback_probe.py`, which generates the Xcode-derived project, builds with production dependencies, verifies FFmpeg linkage, and runs the selected probe with a timeout. Build logs are `build/AetherSoftwareTests/MODE-build.log`. Modes include `native`, `hardware`, and `codecs` in addition to the modes above. Run these scripts/probes sequentially because their generated project/product is shared. No installation, server credentials, or iCloud sync is involved in these playback fixtures.

Keep the [verification history](verification.txt) and codec investigations as dated evidence, not as substitutes for current test runs.

## Device playback checks

These hooks exercise the existing app/player. None runs during an ordinary launch. Device deployment is a separate explicit action; building a project does not authorize installing it on a device currently in use.

- `--stream-smoke-test SHARE RELATIVE_PATH`: stream with saved SMB credentials. Add `--no-playback-history` to avoid modifying bookmarks.
- `--exercise-stream-controls` / `--exercise-mkv-controls`: pause and seek checks; MKV checks also inspect displayed video frames.
- `--exercise-player-lifecycle`: open/dismiss three times, verifying teardown. `--test-second-video RELATIVE_PATH` substitutes the second video; `--probe-frames-only` requires video confirmation.
- `--vp9-diagnostics`: timestamps, queued/late frames, network/cache metrics and thermal state. Cache/read-size overrides are documented in the [streaming investigation](VP9-streaming-investigation.md).
- `--native-tracks-smoke-test --exercise-native-tracks --no-playback-history`: after `python3 tools/create_native_tracks_fixture.py`, copy `build/NativeTrackTests/native-tracks.mp4` into the app's Library/Caches directory to test native audio/subtitle selections.
- Legacy local VP9 control: generate the TV project with `BORAMIN_SMOKE_FIXTURE=/absolute/path/smoke.webm python3 tools/create_project.py`, then use `--smoke-test`. Regenerate without that environment variable afterward. This measures local decoding, not SMB streaming.

The isolated `NativeVP9Probe.swift` project is generated by `tools/create_native_vp9_probe.py --make-fixtures`; see [native VP9](Native-VP9-investigation.md) and [streaming remux](Streaming-remux-investigation.md) for its modes. `NativeAudioProbe.swift` is the retained source of the one-off AAC investigation; its generated app/media have been removed. Temporary logs under `/tmp` and generated products under `build/` are not durable evidence; summarized outcomes are in the committed notes.

## Synthetic CloudKit probe (optional)

`CloudSyncProbe.swift` and `CloudSyncProbeScreen.swift` are test-only fixtures. Normal iOS and Mac builds do not compile them. Enable the iOS probe explicitly:

```sh
python3 tools/create_project.py --include-cloud-probe
# Build the iOS project, then use --probe or --run-id UNIQUE_RUN --cloud-action ACTION.
# After testing, restore the normal project definition:
python3 tools/create_project.py
```

The probe uses the separate `BoraMinSyncProbe-v1` zone and synthetic data. Its delegate skips production sync in probe mode, including background and push handling. Never enter real NAS credentials. The probe uses the current shared app bundle identity; probe-mode data has separate storage/Keychain records. Use a unique run ID and the same iCloud account on test devices; create synthetic records on one device, sync the other, and compare. Never infer Production sync from a Development-only probe.

Production sync has separate `--icloud-sync-check` and `--icloud-preference-check` diagnostics; the latter deliberately edits a preference and requires restoring it afterward. They are not routine app behavior.

## CloudKit scheduling regression

`CloudSyncSchedulingTests.swift` checks that the production engine-task factory discards inherited delegate task-local context while retaining MainActor isolation and cancellation. It runs without a CloudKit account or network access and is included in `tools/run_tests.py`. This guards against the CloudKit task-local-context termination previously observed on Apple TV.

## AetherEngine

MKV routing is automatic (VP9 uses the original hardware path); `--aether-mkv` is obsolete. Use `--aether-diagnostics` with the stream/pixel/seek diagnostics. See [current integration and dated results](../docs/AetherEngine-playback.md).

After an Xcode build, run `python3 tools/verify_media_linkage.py /absolute/path/to/BoraMin.app` to verify that the two FFmpeg builds remain isolated and the private framework uses a bundle-relative install name.
